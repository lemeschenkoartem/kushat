# Чтение номенклатуры с Reference-сервера

Цель пользователя — локальная печать ценников с наименованием, ценой за килограмм
и расчётом цены за 100 г, без платной интеграции White Server и с данными именно
с сервера справочников. Ранее проверявшийся `MIDSERV.exe` был кассовым сервером;
его адрес/порт и каталог нельзя автоматически переносить на Reference-сервер.

## Проверенные официальные источники

21.10.2026 запрос пользовательской страницы
[API](https://docs.rkeeper.ru/rk7/latest/ru/api-19597826.html) вернул HTTP 200.
Сам раздел содержит уведомления об изменениях заказов, AUTHTTP и протокол FarCards;
это не документация чтения номенклатуры.

В [XML-интерфейсе r_keeper 7](https://docs.rkeeper.ru/rk7/latest/ru/xml-interfejs-r_keeper-7-19605640.html)
отдельно описан интерфейс серверов справочников/отчётов. Его возможности включают
чтение элементов справочников и выгрузку меню/цен. Для HTTPS в статье указаны:

- Раздел менеджера **Настройки → OLAP отчёты → Серверы отчётов**.
- Свойства выбранного сервера: **HTTP Server → HTTP Data Port**, ограничения HTTP
  и привилегии сотрудника. У сотрудника должны быть нужные роль и права.
- Путь запроса: `/rk7api/v0/xmlinterface.xml` через HTTPS.
- Веб-форма тестирования: `/webgui/iservxmltest.htm` на адресе и HTTPS-порту этого сервера.

Статья архивная и прямо указывает, что новые интеграции настраиваются через White Server,
а приведённая информация относится к действующим решениям. Наличие технического описания
не является подтверждением коммерческих условий или доступности на конкретной установке.

## Лицензирование и границы проверки

[Раздел лицензирования XML по подписке](https://docs.rkeeper.ru/rk7/latest/ru/ispol-zovanie-xml-interfejsa-po-podpiske-43455727.html)
требует LicenseInfo для `SaveOrder`, `PayOrder`, `MakeRetunGoods` (написание в документации).
Печатная программа эти операции не выполняет. Отдельного явного утверждения о бесплатности
новой интеграции `GetRefData` в прочитанных источниках не найдено. Нельзя переносить требования
сохранения заказов на любое чтение или обещать отсутствие платы без проверки условий.
Следующий технический шаг — проверка разрешённого чтения на действительном Reference-сервере,
без приобретения новых лицензий и без изменений данных R-Keeper.

## Запросы и формат цен

[Запрос справочников](https://docs.rkeeper.ru/pages/viewpage.action?pageId=189235377)
описывает `GetRefData`, макросвойства, маску полей и пагинацию.
[Рекомендации](https://docs.rkeeper.ru/pages/viewpage.action?pageId=186253740)
предлагают отслеживать версии через `GetRefList` не чаще одного раза в 10 минут,
а большие справочники читать частями с `Offset` / `ItemCount`.

[Получение актуального меню](https://docs.rkeeper.ru/pages/viewpage.action?pageId=47644998)
разделяет справочник `MENUITEMS` и доступность/цены конкретной кассовой станции.
Для Reference-сценария нельзя требовать кассовые операции или подменять справочные цены
контекстными ценами станции без решения пользователя.

В версии 0.2.0 запросы используют `RK7Command`; поддержаны ответы с `CommandResult`
и одиночный `RK7Reference` непосредственно в `RK7QueryResult`.
Служебное значение `9223372036854775807` пропускается. В разных ответах используются
разные представления: для `GetOrderMenu` документация явно указывает копейки; это
не доказывает единицы макросвойств `GetRefData`. Перед эксплуатацией нужно сверить
реальные цены выбранного типа. Обработчик макросвойств по-прежнему ожидает рубли.

## Весовые и штучные товары

[Создание весового блюда](https://docs.rkeeper.ru/pages/viewpage.action?pageId=43454891)
и [справочник Меню](https://docs.rkeeper.ru/pages/viewpage.action?pageId=4037802)
описывают три разных режима цены: штучное, за единицу веса и за стандартную порцию.
Точность количества не является признаком весового товара: штучное блюдо тоже
можно продавать дробным количеством. Единица и вес порции важны для пересчёта.

В [структуре данных](https://docs.rkeeper.ru/pages/viewpage.action?pageId=105879434)
указаны `PriceMode`, `PortionName`, `PortionWeight` (int64 в нативном описании).
В [CreateDish](https://docs.rkeeper.ru/pages/viewpage.action?pageId=204898604)
даны режимы `PerPiece`, `PerPortion`, `PerUnitOfWeight` и вес порции в граммах.
Последняя статья относится к White Server: она использована как дополнительная
справка о значениях, транспорт приложения остаётся прямым Reference XML.

Обработчик 0.2.0 принимает нативные имена `pmPerPiece`, `pmPerPortion`,
`pmPerUnitOfWeight`; для стандартной порции ожидается целочисленный вес в граммах.
Соответствие полей конкретной установке надо проверить по её ответу и карточке блюда.
Отсутствующий/неизвестный режим, неподдерживаемая единица и некорректный вес порции
не трактуются как кг или штуки: строка видна, но печать запрещена.
Пересчёт цены и округление проверяются отдельно для килограмма и 100 г.

## HTTPS-сертификат

Документирован пользовательский файл **`mylocal.pem`** в `BaseData\httpKeys`.
См. [утилиту 2.0.0 и пошаговую настройку](reference-certificate.md), а также [историю ошибки с default.pem](local-certificate.md).
На установке пользователя подтверждены успешная установка `mylocal.pem`, импорт публичного сертификата
и ответ HTTP 401 без ошибок TLS на `https://127.0.0.1:8010`. После настройки учётной записи
пользователь сообщил об успешной работе. Это не заменяет сверку цен на других объектах.

SDK `RK7XML.dll` и драйвер `iTCPXML.dll` — разные компоненты. В статье для SDK описано
добавление TCP-драйвера на кассовый сервер; это не подтверждает такой транспорт Reference-сервера.
В официальном ABI `CallRK7XMLRPC2` пятый параметр — `var RequestNum: DWord`, а не размер ответа.
Архивированный неопубликованный TCP-черновик нельзя считать протестированной реализацией.


## Группы меню и навигация — 0.5.0

[Получение актуального меню](https://docs.rkeeper.ru/pages/viewpage.action?pageId=47644998)
содержит пример `CATEGLIST` / `TCategListItem` (группы меню) и ссылки `Parent` /
`MainParentIdent` у блюд. В [структуре данных](https://docs.rkeeper.ru/pages/viewpage.action?pageId=105879434)
также определены группы меню `CATEGLIST`.

После чтения цен и блюд программа отдельно читает `GetRefData RefName="CategList"`
с `OnlyActive="1"`, `WithChildItems="1"`. По [описанию запроса](https://docs.rkeeper.ru/pages/viewpage.action?pageId=189235377)
это включает собственную иерархию справочника в `RIChildItems`, с именами классов
в тегах. Парсер принимает прямые `Items/Item` и вложенные `RIChildItems/TCategListItem`,
не трактуя блюда/модификаторы из других коллекций как папки.

`Parent` (или `MainParentIdent`) сохраняется при выборе типа цены. Выбор папки
фильтрует также её подветки. Группы с отсутствующим родителем поднимаются на верхний
уровень; циклы разрываются, чтобы дерево оставалось доступным. Товары без найденной
группы не теряются и доступны через общий список и «Без доступной группы».
Если группы недоступны (403/404 или недопустимый XML справочника), уже загруженные
товары доступны в общем списке с пояснением. Ошибка авторизации 401 не скрывается.

На ценнике и в таблице 0.5.0 остаётся одна цена: за 100 г либо за штуку.
Цена за кг продолжает использоваться только для внутреннего пересчёта весовой цены.
