# Сертификат HTTPS для Reference-сервера: утилита 2.0.0

Утилита проекта «Кушать», не официальный продукт UCS. Для локальной сети публичный
платный сертификат не требуется: создаётся собственный сертификат, которому доверяют
конкретные компьютеры клиента. Проверка TLS остаётся включённой.

[Скачать Windows x64 ZIP, версия 2.0.0](https://github.com/lemeschenkoartem/kushat/raw/refs/heads/downloads/Kushat-CertificateTool-2.0.0-win-x64.zip).
Архив автономный, отдельная установка .NET не требуется. Внутри нет сертификатов или
закрытых ключей: они создаются локально при `prepare`.

Основание: официальная статья
[«Использование валидных SSL-сертификатов для сервера отчетов в домене»](https://docs.rkeeper.ru/pages/viewpage.action?pageId=77467573).
Собственный PEM с сертификатом и ключом устанавливается как **mylocal.pem** рядом с
`default.pem`, затем сервер перезапускается. RSA 2048, SHA256. Совместимость с конкретной
сборкой проверяется по сертификату, предъявляемому после запуска сервера.

Версия 1.0.0 заменяла `default.pem`; на прежнем кассовом сервере это не сработало.
Не используйте старую утилиту и старую папку подготовки. В версии 2.0.0 команды
`install`/`rollback` принимают только новую подготовку и работают с `mylocal.pem`.

## Подтверждённые параметры текущего сервера

- Адрес Reference API: `https://192.168.7.2:8010`.
- Процесс: `F:\RK7888\RK7888\Rk7Reference\RefSrv.exe`.
- Файл по умолчанию: `F:\RK7888\RK7888\Rk7Reference\base\httpKeys\default.pem`.
- На 21.10.2026 порт доступен, но Windows сообщает `SEC_E_CERT_EXPIRED`.

Это данные текущей установки, не универсальные пути R-Keeper. На другом сервере
сначала определите активный процесс порта и его каталог `httpKeys`.

## 1. Подготовка на сервере 192.168.7.2

Проверьте дату и время Windows. Распакуйте новую утилиту в отдельную папку
`C:\Kushat-Reference-Certificate`. Откройте PowerShell от имени администратора:

```powershell
Set-Location 'C:\Kushat-Reference-Certificate'
.\Kushat.CertificateTool.exe --version
.\Kushat.CertificateTool.exe prepare 'F:\RK7888\RK7888\Rk7Reference' 'F:\RK7888\RK7888\Rk7Reference\base\httpKeys' '192.168.7.2'
```

В выводе версии должно быть **2.0.0 — Reference / mylocal.pem**.
Подготовка не меняет рабочие PEM и не останавливает сервер. Создаётся уникальная
папка `httpKeys\Kushat-reference-<время>-<идентификатор>` с ограниченным доступом:
текущий пользователь, администраторы, SYSTEM. Сохраните её полный путь из вывода:

```powershell
$rkPrepared = 'ПОЛНЫЙ ПУТЬ К НОВОЙ ПАПКЕ ИЗ ВЫВОДА prepare'
```

В папке: `mylocal.new.pem`, публичный `rkeeper-local.cer`, `certificate-info.txt`,
`preparation.json`; если `mylocal.pem` уже существовал — также `mylocal.before.pem`.
PEM содержат закрытые ключи: не отправляйте их в чат, почту или GitHub.
Срок — два года; SAN включает `192.168.7.2`, `127.0.0.1`, `::1`, `localhost`, `rk7.local`.
Для другого IP/DNS потребуется новая подготовка с этим адресом.

## 2. Установка в согласованное время

Остановите **этот Reference-сервер** штатным способом, когда перерыв допустим.
Если он работает службой, найдите её по пути `RefSrv.exe` в `services.msc` и остановите
именно её; если приложением — завершите штатной командой сервера. Не используйте
принудительное завершение. Утилита сама процессами и службами не управляет.

```powershell
.\Kushat.CertificateTool.exe install $rkPrepared
```

Команда отказывает, пока соответствующий `RefSrv.exe` работает, если не удаётся
проверить его путь, изменились подготовленные файлы или состояние `mylocal.pem`.
При новом файле права доступа копируются с `default.pem` ещё до записи ключа;
при замене существующего сохраняются его владелец и ACL. `default.pem` не меняется.
При обычной ошибке записи выполняется восстановление предыдущего состояния.
Аварийное выключение питания требует ручного восстановления из резервной копии.

После успеха запустите тот же Reference-сервер штатным способом. Замена сертификата
относится ко всем HTTPS-клиентам этого экземпляра: клиентам с системной проверкой
потребуется доверие к новому сертификату.

## 3. Доверие на компьютере с приложением «Кушать»

На сервере получите SHA256 **публичного** файла:

```powershell
certutil -hashfile "$rkPrepared\rkeeper-local.cer" SHA256
```

Он должен совпасть с SHA256 в `certificate-info.txt`. Если приложение на другом
компьютере, перенесите туда **только `rkeeper-local.cer`** и сверьте SHA256.
Под пользователем Windows, запускающим приложение, откройте этот `.cer`:
**Установить сертификат → Текущий пользователь → Поместить все сертификаты в следующее
хранилище → Доверенные корневые центры сертификации → Готово**.

На самом сервере под тем же пользователем вместо мастера можно выполнить:

```powershell
Import-Certificate -FilePath "$rkPrepared\rkeeper-local.cer" -CertStoreLocation Cert:\CurrentUser\Root
```

Импорт из-под другой административной учётной записи добавит доверие для неё,
а не для пользователя приложения. Утилита сама хранилище Windows не меняет.

## 4. Проверка

Под пользователем приложения выполните:

```powershell
curl.exe -v --max-time 10 https://192.168.7.2:8010/rk7api/v0/xmlinterface.xml
```

Нужен HTTP-ответ **без ошибки TLS**. HTTP 401 на запрос без пароля означает, что
TLS прошёл, сервер требует авторизацию. Это ещё не проверка чтения номенклатуры.
Если ошибка срока сохранилась, не повторяйте установку вслепую: проверьте, что
запущен именно нужный RefSrv и он предъявляет новый сертификат.

Для строгой проверки предъявленного отпечатка на том же компьютере можно выполнить
(обычная проверка цепочки и имени включена; обхода TLS нет):

```powershell
$rkTcp = [System.Net.Sockets.TcpClient]::new('192.168.7.2', 8010)
$rkTls = [System.Net.Security.SslStream]::new($rkTcp.GetStream(), $false)
try {
    $rkTls.AuthenticateAsClient('192.168.7.2')
    $rkHash = [System.Security.Cryptography.SHA256]::Create()
    try {
        ([BitConverter]::ToString($rkHash.ComputeHash($rkTls.RemoteCertificate.GetRawCertData()))).Replace('-', '')
    } finally { $rkHash.Dispose() }
} finally { $rkTls.Dispose(); $rkTcp.Dispose() }
```

Выведенный SHA256 должен совпасть с `certificate-info.txt`.
В программе используйте **`https://192.168.7.2:8010`**, затем логин и пароль сотрудника
с правом HTTP/XML-доступа. Ключ от TCP-драйвера и AgentGuid здесь не используются.
Реальные чтение меню, формат ответа и единицы цены проверяются после исправления TLS.

## Откат

Если новый PEM не принимается, остановите тот же RefSrv штатным способом:

```powershell
.\Kushat.CertificateTool.exe rollback $rkPrepared
```

Если до подготовки `mylocal.pem` отсутствовал, удалится только файл с ожидаемой
контрольной суммой новой установки. Если существовал — восстановится резервная копия.
Изменённый сторонними действиями `mylocal.pem` не удаляется и не перезаписывается.
Затем запустите RefSrv. При возврате к прежнему просроченному сертификату TLS снова
будет отклоняться, но исходное состояние файлов восстановится. Папку подготовки
сохраняйте до проверки эксплуатации.

## Проверки разработчика

`scripts/check.sh`: 81 тест, включая реальное TLS с доверенной локальной цепочкой и
проверкой SAN `192.168.7.2`, сохранение `default.pem`, установку/откат при наличии и
отсутствии исходного `mylocal.pem`, запрет при работающем сервере через внедрённую
проверку, отказ при изменённых файлах. Кросс-сборки WPF и утилиты проходят на Linux.
Windows ACL, чтение процессов и загрузка PEM реальным RefSrv в облаке не проверены.

```powershell
dotnet publish tools/Kushat.CertificateTool/Kushat.CertificateTool.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o artifacts/reference-certificate-win-x64
```
