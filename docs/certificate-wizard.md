# Мастер сертификата — 0.4.0

Откройте **«Сертификат…»** в программе или запустите `Certificate-Wizard.cmd`
**на компьютере Reference-сервера**. IP и порт вводить не нужно.
Для установки сертификата и управления службой Windows нужны права администратора.

## Проверить и заменить сертификат

1. Мастер автоматически ищет службы и процессы `RefSrv.exe`, их каталоги и файлы
   `base\httpKeys\mylocal.pem`/`default.pem`. При нескольких установках выберите нужный
   сервер. Если база вне каталога установки, доступна **«Папка httpKeys…»**.
2. Показываются путь сертификата, срок действия и SHA256. При работающем сервере
   HTTPS-порт определяется по его процессу автоматически и используется для
   сопоставления активного сертификата с файлом. Для остановленного сервера
   проверяется `mylocal.pem`, если он существует; иначе `default.pem`.
   Просроченный старый `default.pem` не делает действующий `mylocal.pem` просроченным.
3. Если срок истёк или ещё не наступил, **«Далее» недоступна**. Нажмите
   **«Выпустить новый сертификат»**. Если сертификат подходит, **«Далее»** настроит
   доверие и откроет завершение без перевыпуска и перезапуска. При сроке менее 30 дней
   показано предупреждение; новый сертификат можно выпустить заранее.
4. При выпуске создаются ключ RSA 2048, сертификат на два года, резервная копия
   прежнего `mylocal.pem` и публичный `rkeeper-local.cer`. Имена компьютера и текущие
   IP активных сетевых интерфейсов включаются в SAN автоматически, вместе с
   `localhost`, `127.0.0.1`, `::1`, `rk7.local`. На этом шаге рабочий файл не меняется.
5. На экране **«Отключите Reference-сервер»** нажмите **«Остановить службу»** или
   остановите её штатно вручную. Мастер дождётся остановки службы, завершения
   процесса и освобождения его найденных портов. Только тогда появится **«Далее»**.
6. Нажмите **«Далее»**. Устанавливается `mylocal.pem`, публичный сертификат
   добавляется в доверенные Windows LocalMachine Root. `default.pem` не меняется.
   Появится **«Сервер можно включить»**.
7. Нажмите **«Запустить службу»** или запустите её штатно вручную. Мастер найдёт
   HTTPS-порт по новому процессу и проверит срок, имя, доверие и точное совпадение
   SHA256 с установленным сертификатом. Чужой или старый сертификат не завершит настройку.
8. После успешной проверки нажмите **«Далее» → «Завершить»**.

Если HTTPS-порт не найден при проверке уже действующего файла, мастер прямо сообщает,
что проверен файл, а не доступность HTTPS. Перед входом программа печати отдельно
проверит порт. После замены сертификата проверка запущенного HTTPS обязательна.
Если приложение RefSrv работает без службы, остановите/запустите его вручную;
кнопки управления службой будут недоступны.

## Назад и отмена

**«Назад»** возвращает на один экран. До установки можно вернуться к поиску и выбрать
другой сервер. После установки сертификат остаётся установленным: повторный переход
вперёд не перезаписывает его. Выбор другой установки блокируется до завершения или
отката. Возврат с итогового экрана требует повторной проверки запуска перед завершением.

**«Отмена»** и крестик закрывают мастер. Поиск и сетевые проверки можно отменить;
запись файла заканчивается до выхода. Если сертификат уже установлен или сервер
остановлен в ходе настройки, мастер показывает фактическое состояние и предлагает
подтвердить выход. При выходе служба автоматически не запускается и не останавливается,
установленный сертификат сохраняется. Для восстановления используйте явный откат.

## Откат

Остановите службу. После подтверждённой остановки станет доступно
**«Откатить сертификат»**. Мастер проверяет контрольные суммы и восстанавливает прежний
`mylocal.pem`, либо удаляет только созданный им файл, если раньше его не было.
Удаляется только добавленное этим мастером доверие к новому сертификату.
Запустите сервер. Исходная ошибка сертификата при этом может вернуться; просроченный
сертификат не становится действующим после отката. Для выхода доступна **«Отмена»**.

Резервные копии остаются в `httpKeys\Kushat-reference-*`, доступны только текущему
пользователю, администраторам и SYSTEM. PEM содержат закрытые ключи; другим компьютерам
передавайте только публичный `.cer`. При смене IP после выпуска может понадобиться
новый сертификат. Для ручного восстановления есть [инструкция CLI](reference-certificate.md).

## Программа печати на другом компьютере

Мастер поиска запускают на Reference-сервере. На клиенте в окне входа укажите
**HTTPS-адрес** сервера, нажмите **«Доверие из .cer…»** и выберите публичный
`rkeeper-local.cer`, полученный с этого сервера. Проверяются срок, имя, Server
Authentication и совпадение SHA256 файла с сертификатом на порту. Затем добавляется
доверие и повторяется строгая проверка HTTPS.

При обычном запуске доверие добавляется текущему пользователю (Windows может запросить
подтверждение), при запуске от администратора — компьютеру. Неизвестный сертификат
из сети автоматически в доверенные не добавляется. Корпоративную цепочку УЦ настраивают
средствами вашей инфраструктуры.

## HTTP и HTTPS

Программа поддерживает оба протокола. Новый сертификат не меняет протокол порта.
Для HTTPS-порта укажите `https://…`, для отдельно настроенного HTTP-порта — `http://…`.
В вашей проверенной установке Reference отвечал через `https://127.0.0.1:8010`.
HTTP-запрос к этому TLS-порту может завершиться `HTTP_RESPONSE`.

Перед входом, автовходом и обновлением меню программа проверяет TCP-порт и, для HTTPS,
сертификат без отправки пароля. При ошибке TLS авторизация не начинается. Для HTTP
сертификат не используется. Проверка TLS не отключается и после предварительной проверки.

## Проверки сборки

Тестируются сроки и блокировка завершения, навигация назад без повторной установки,
выбор активного сертификата и SAN нескольких адресов, реальные TCP/TLS-сеансы,
отсутствие авторизации до успешной проверки. На Windows проверяются начальное окно
без полей IP/порта, отмена, системное чтение состояния службы, обнаружение локальных
служб и слушающих адресов, установка/откат файлов с ACL и строгое TLS-доверие.
Рабочие службы RefSrv в автоматических тестах не останавливаются.
