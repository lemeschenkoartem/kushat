# Мастер сертификата и проверка соединения — 0.3.0

Мастер включён в тот же `Kushat.exe`; отдельные команды PowerShell для обычной
настройки не требуются. Запустите **«Сертификат…»** в главном окне,
**«Мастер сертификата…»** в окне входа либо `Certificate-Wizard.cmd` из архива.
Последний вариант открывает мастер без входа в R-Keeper и без загрузки меню.
Для управления службой и доверия всем пользователям Windows нужны права администратора.
Программа запрашивает повышение прав через обычное окно Windows.

## На компьютере Reference-сервера

1. Укажите HTTPS-адрес и порт. При запуске из программы подставляется текущий адрес.
   Мастер ищет службы и процессы `RefSrv.exe`, их слушающие порты и каталоги `httpKeys`
   внутри установки. Если адрес пуст, проверяет до восьми портов выбранного процесса
   и ищет HTTPS-сертификат. При нескольких серверах выберите нужный.
2. Нажмите **«Найти и проверить»**. Показываются доступность порта, срок, SHA256,
   совпадение имени, файлы `default.pem`/`mylocal.pem`. Предъявляемый сервером файл
   отмечается отдельно. Вложенные каталоги подготовки и BACKUPS не сканируются.
   Если база находится за пределами каталога RefSrv, выберите её **«Папка httpKeys…»**.
3. Если сертификат подходит, но только не настроено доверие, мастер может добавить
   проверенный локальный публичный сертификат без замены файла и перезапуска.
   Если всё уже исправно, **«Далее»** ведёт сразу к завершению.
4. Для замены просроченного или неподходящего сертификата оставьте **«Выпустить новый
   сертификат»** и нажмите **«Далее»**. Мастер подготовит собственный ключ RSA 2048,
   сертификат на два года с указанным IP/DNS и loopback-адресами, резервную копию
   существующего `mylocal.pem` и публичный `rkeeper-local.cer`.
5. На шаге **«Отключите Reference-сервер»** штатно остановите выбранную службу кнопкой
   **«Остановить службу»** либо через службы Windows, в допустимое время.
   Мастер проверяет состояние службы, отсутствие процесса из этого каталога и
   отсутствие слушающего порта. **«Далее» появляется только после всех трёх проверок**.
6. Нажмите **«Далее»**. Устанавливается `mylocal.pem` с сохранением подходящих прав
   доступа и добавляется доверие к публичному сертификату в Windows LocalMachine Root.
   `default.pem` не меняется. Появится сообщение **«Сервер можно включить»**.
7. Нажмите **«Запустить службу»** либо запустите её обычным способом. Мастер дождётся
   работающих службы и процесса, открытого порта и успешной системной проверки HTTPS.
   SHA256 предъявляемого сертификата должен совпасть именно с подготовленным.
8. После проверок появится **«Далее»**, затем итоговый экран и кнопка **«Завершить»**.

Остановка и запуск выполняются только для выбранной службы после проверки её пути.
Принудительное завершение RefSrv не используется. Если RefSrv запущен обычным
приложением без службы, остановите и запустите его штатно вручную: мастер всё равно
контролирует процесс/порт и не допускает переход раньше времени.

Подготовка и резервная копия остаются в `httpKeys\Kushat-reference-*` с доступом
только текущему пользователю, администраторам и SYSTEM. В PEM есть закрытые ключи;
другим компьютерам передаётся только публичный `.cer`.

## Если программа печати на другом компьютере

Замену файла и перезапуск выполняйте на Reference-сервере. На клиентский компьютер
перенесите только `rkeeper-local.cer` из подготовки на сервере.
Откройте мастер с адресом этого сервера и нажмите **«Доверие из публичного .cer…»**.
Мастер проверит срок, имя, назначение Server Authentication и точное совпадение
SHA256 файла с сертификатом на порту, добавит доверие и повторит строгую проверку.

При запуске от администратора доверие устанавливается для компьютера, при обычном
запуске — для текущего пользователя. Мастер принимает для этого сценария только
публичный самоподписанный серверный сертификат, не закрытый ключ и не сертификат УЦ.
Корпоративную цепочку УЦ настраивают средствами вашей инфраструктуры.
Неизвестный сертификат из сети автоматически в доверенные не добавляется.

## Откат

Если новый PEM не принят или нужно вернуть прежнее состояние, остановите выбранную
службу. После подтверждённой остановки станет доступно **«Откатить сертификат»**.
Мастер проверяет контрольные суммы и возвращает прежний `mylocal.pem` либо удаляет
только созданный им файл, если раньше его не было. Удаляется только добавленное этим
мастером доверие к новому сертификату. Затем запустите службу и дождитесь проверки
исходного отпечатка. Исходная ошибка просроченного сертификата при этом может вернуться.

Если доверие не удалось добавить сразу после установки, мастер пытается вернуть
прежнее состояние файла до перехода к запуску. Резервная копия сохраняется.
Защита от внезапного отключения питания не гарантируется; ручной откат по резервной
копии выполняется при остановленном сервере, как описано в [инструкции CLI](reference-certificate.md).

## Проверка перед входом

При ручном и автоматическом входе, а также обновлении меню, программа сначала
проверяет TCP-порт и выполняет HTTPS-handshake **без логина и пароля**.
Проверяются срок, имя и доверенная цепочка. Только после успеха отправляются запросы
авторизации и чтения меню. В окне входа есть отдельная кнопка
**«Проверить порт и сертификат»**, работающая без учётных данных.
При действующем HTTPS-соединении в главном окне отображается срок сертификата.
Если осталось менее 30 дней, проверка сообщает об этом.

Для явно выбранного HTTP проверяется порт, а в результате указывается, что TLS
и сертификат не используются. Мастер не переводит HTTPS в HTTP при ошибке.
Проверка на стороне HTTP-клиента остаётся включённой и после предварительной проверки.

## Границы проверок

Проверяются переходы мастера, реальные TCP/TLS-сеансы, отсутствие авторизации до
успешной проверки, поиск файлов и отказ при неоднозначности. На Windows проверяются
системное чтение состояния службы, обнаружение локальных служб, установка и откат
файлов с ACL, добавление уникального тестового публичного сертификата в CurrentUser
Root и строгая проверка TLS после этого (с удалением тестового доверия).
Остановка и запуск рабочего RefSrv проверяются на объекте; тесты не останавливают
производственные службы. Фактический выбор `mylocal.pem` модулем R-Keeper подтверждается
проверкой отпечатка после запуска.
