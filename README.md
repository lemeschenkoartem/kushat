# Кушать — ценники для Windows

Приложение для печати ценников 14 × 10 см на А4: наименование, цена за 1 кг и за 100 г.
Четыре ценника на листе, выбор нескольких товаров, отдельный тираж каждого товара,
предварительный просмотр и выбор локального или установленного сетевого принтера Windows.

## Скачать и запустить

[**Скачать сборку 0.1.2 с HTTP для Windows x64 (ZIP)**](https://github.com/lemeschenkoartem/kushat/raw/refs/heads/downloads/Kushat-HTTP-0.1.2-win-x64.zip)

Архив размещён в отдельной ветке `downloads`; рядом находится `SHA256SUMS`.

Закройте ранее запущенную программу. Распакуйте `Kushat-HTTP-0.1.2-win-x64.zip` в новую папку
и запустите `Kushat.exe` из неё на Windows 10 22H2 / Windows 11 x64.
Это автономная сборка: отдельно устанавливать .NET не требуется.
В заголовке окна входа должно быть **«0.1.2 · HTTP/HTTPS»**.
Сообщение «Укажите HTTPS-адрес сервера…» относится к старой сборке.

1. Нажмите **«Войти в R-Keeper»**.
2. Укажите адрес сервера с портом встроенного XML-интерфейса R-Keeper, логин сотрудника и пароль.
3. Нажмите **«Войти и загрузить меню»**. Вход считается выполненным после успешного чтения меню и типов цен.
4. Выберите **тип цены**. Если тип один, он выбирается автоматически.
5. Отметьте товары и количество ценников для каждого.
6. Выберите принтер Windows, проверьте предварительный просмотр и нажмите **«Напечатать…»**.

Пароль используется только в текущем сеансе и не сохраняется в настройках.
Кнопка **«Выйти»** очищает пароль и загруженные данные текущего сеанса.
Адрес и логин сохраняются в `%LOCALAPPDATA%\Kushat\settings.json` вместе с выбранным принтером.
Для проверки печати без сервера есть **«Демо-товары»** — ценники будут помечены как демонстрационные.

## Что именно подключается

WSA2 и AgentGuid в этой версии не используются. Приложение обращается непосредственно к встроенному
HTTP/HTTPS XML-интерфейсу сервера R-Keeper: `/rk7api/v0/xmlinterface.xml`, авторизация HTTP Basic.
Запрашиваются только `GetRefData` для `PriceTypes` и `MenuItems` с макросвойствами цен.
Это доступ через интерфейс сервера R-Keeper, **не прямое SQL-соединение с базой**.
Логин сотрудника R-Keeper не является автоматически логином СУБД.

На сервере должны быть включены XML-интерфейс, соответствующий HTTP- или HTTPS-порт, разрешения сотрудника и необходимые лицензии.
Порт XML-интерфейса может отличаться от порта подключения R-Keeper Manager.
В поле адреса можно указать `http://сервер:порт`, `https://сервер:порт` или имя/IP с портом.
Для адреса без протокола используется **HTTP**. Явно указанный HTTPS сохраняется.
При HTTPS сертификат сервера должен быть доверенным в Windows; обычная проверка TLS сохраняется.

Для проверки на том же компьютере можно использовать адрес вида `http://127.0.0.1:порт`.
С другого компьютера локальной сети укажите IP или имя компьютера, на котором запущен нужный сервер.
`127.0.0.1` всегда означает текущий компьютер.

Ошибка `ERR_CONNECTION_REFUSED` означает, что соединение по выбранному адресу и порту не принято.
Она сама по себе не указывает на проблему сертификата. Проверьте, запущен ли HTTP-интерфейс и какой порт он слушает.
Порт TCP XML-драйвера `iTCPXML.dll` нельзя автоматически считать HTTP-портом: это другой протокол.

**Совместимость с реф-сервером клиента версии 7.25.08.005 пока не проверена.**
Запросы и формат адаптера основаны на открытых примерах, перечисленных в [examples/README.md](examples/README.md).
Если интерфейс на клиентском реф-сервере не поддерживает такой обмен, необходимы его документация/пример ответа и адаптация.
Если требуется именно SQL-доступ, дополнительно нужны тип СУБД, имя базы, схема данных и отдельные права на чтение.

## Диагностика подключения

В версии 0.1.2 вместо общего сообщения об ошибке связи показывается код причины:
`CONNECTION_REFUSED`, `DNS_FAILURE`, `TLS_CERTIFICATE`, `TLS_HANDSHAKE`, `HTTP_401`, `HTTP_403` и другие.
Кнопка **«Скопировать ошибку»** копирует диагностический текст для поддержки.
В него не включаются пароль, заголовок Authorization, тела запросов/ответов и исходные сетевые сообщения.

При ошибке сертификата выводятся результат системной проверки Windows, состояния цепочки,
имя и срок действия сертификата, а также его SHA256-отпечаток. Сертификат при этом не принимается автоматически.
Если браузер открывает страницу после исключения для сертификата, это ещё не означает доверие к нему в Windows/.NET.
Проверьте срок, дату/время ПК, соответствие DNS-имени в адресе и доверенную цепочку.
Доверие настраивается после проверки сертификата у администратора сервера; проверка TLS в приложении сохраняется.

Для подтверждённого просроченного `midbase/httpKeys/default.pem` с отпечатком
`E386054B1BBC16C3F4D54C95D03CB1CCD97E317B0B1AE7EC622179A75A447A8B`
подготовлена [запись диагностики и ограничения утилиты](docs/local-certificate.md).
**На сервере пользователя прямая замена не сохранилась после запуска MIDSERV:** рабочий файл
снова совпал с исходным. Не повторяйте замену и остановку сервера; сначала нужна подтверждённая
настройка пользовательского сертификата для конкретной сборки R-Keeper.
Позднее в официальной документации найдена настройка `mylocal.pem` для сервера
отчётов/справочников; её область действия и необходимые проверки приведены по ссылке выше.
Документированное подключение к Reference-серверу разобрано в [заметке](docs/reference-server.md).

Ошибка `TLS_HANDSHAKE` без сведений о сертификате также может указывать на несовместимые настройки TLS.
Неверный пароль и запрет доступа показываются отдельно как HTTP 401/403.

## Товары и цены

Тип цены выбирается явно, если их несколько. Значения читаются из макросвойств `PRICETYPES-<Ident>` в меню,
в рублях. Позиции без цены выбранного типа не предлагаются для печати; их число показано в статусе.
При отсутствии цен, некорректном ответе, ошибке входа или отказе сервера успешный вход не имитируется.
При HTTP 401/403 во время обновления текущий сеанс сбрасывается.
При временной ошибке связи предыдущие данные остаются, но цены не считаются обновлёнными.

Перед эксплуатацией сверьте несколько цен с R-Keeper. Выбирайте товары, цена которых задана за килограмм:
единица измерения автоматически не определяется.
Цена за 100 г рассчитывается делением на 10 с округлением до копеек от середины вверх:
315,55 ₽/кг → 31,56 ₽/100 г.

Поиск не сбрасывает выбор: в печать попадут все отмеченные товары, включая скрытые поиском.
Обновление меню, смена типа цены и выход сбрасывают выбранные позиции после подтверждения.
За один раз можно напечатать до 1000 ценников; для одного товара — от 1 до 999 экземпляров.

## Размеры и печать

А4, книжная ориентация, два столбца по 100 мм и два ряда по 140 мм.
Поля слева/справа — 5 мм, сверху/снизу — 8,5 мм. Рамка помогает разрезать лист.
Масштаб 100%, без подгонки размера и без двусторонней печати.
Тираж каждого товара уже включён в документ.

Программа проверяет доступную область печати драйвера и отказывает, если ценники не помещаются.
Первый лист следует измерить линейкой: рамка должна быть 100 × 140 мм.
Для проверки в PDF можно выбрать установленный **Microsoft Print to PDF**.
На Linux GUI и физическая печать не проверяются — для этого нужна Windows с принтером.

## Сборка и проверки

Нужен .NET SDK 10. Из корня репозитория:

```powershell
dotnet test tests/Kushat.Core.Tests/Kushat.Core.Tests.csproj -c Release
dotnet run --project src/Kushat.App/Kushat.App.csproj
```

Автономный EXE и ZIP для Windows x64:

```powershell
./scripts/build-windows.ps1
```

Результат: `artifacts/reference-win-x64/Kushat.exe`, `artifacts/Kushat-HTTP-0.1.2-win-x64.zip`
и копия архива с постоянным именем `artifacts/Kushat-reference-win-x64.zip`.
В Linux можно выполнить `bash scripts/check.sh`: тесты логики и сборка WPF для Windows.
Тесты проверяют расчёты, тиражи, А4, авторизацию, XML-запросы/ответы, выбор типа цены и обработку отказов.
Ответы сервера в тестах искусственные; реальный вход у клиента и физическая печать требуют отдельной проверки.

## Передача программы через GitHub

Рабочие файлы облачной среды могут не скачиваться по ссылкам из чата.
Для устойчивой передачи подготовлен `.github/workflows/windows-release.yml`.
После загрузки исходников в репозиторий можно запустить **Actions → Windows build and release → Run workflow**.
После успешной сборки ZIP будет в разделе **Artifacts** этого запуска (для скачивания требуется вход в GitHub).

Для выпуска в **Releases** отправьте новый тег вида `v0.1.0` на нужный коммит.
Только отправка тега запускает публикацию релиза; ручной запуск собирает артефакт без публикации.
Релиз и файл для скачивания появляются после успешного завершения обеих задач workflow.
